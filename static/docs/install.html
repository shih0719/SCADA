Part 1 · Installation

安裝架設

給負責架設系統的人：從準備主機、安裝程式、先用模擬器試跑，到正式上線、設成開機自動啟動。 架好之後，空間、設備、迴路的設定請看配置使用。

01系統架構

整套系統是一支 Node.js 程式，同時負責三件事：提供網頁畫面與 API、在背景定時向 Modbus 設備讀取迴路狀態，以及依排程自動套用場景。 資料存在本機的 SQLite 檔案，不需要另外安裝資料庫。

  • 瀏覽器不會直接連 Modbus 設備；畫面上的燈號是伺服器最近一次輪詢的結果，會有 1～2 秒延遲。
  • 伺服器重啟後，迴路狀態要等下一輪輪詢才會恢復；設定資料存在 SQLite，不會遺失。
  • 排程依伺服器主機的本機時間執行，請確認主機時區與時間正確。

02環境需求

項目需求
作業系統Windows 10/11、Windows Server，或 Linux（x64 / arm64）。
Node.js22.17 以上（SvelteKit 3 的最低需求）。到 nodejs.org 下載 LTS 版，安裝時會一併裝好 npm。
網路主機要能連到每台 Modbus TCP Gateway（通常是 TCP 502）；操作人員的電腦要能連到這台主機的網頁 port（預設 3000）。
硬碟程式約 300 MB（含 node_modules）；資料視平面圖數量而定，通常幾十 MB 以內。
瀏覽器新版 Chrome、Edge、Firefox 或 Safari。頁首的動態背景需要 WebGPU，不支援時會自動改成靜態背景，不影響功能。

確認 Node.js 版本：

node -v
# 應顯示 v22.17.0 或更新
關於 better-sqlite3

資料庫套件 better-sqlite3 是原生模組。常見平台在 npm install 時會直接下載預先編譯好的檔案；如果主機沒有網路，或是平台比較少見，就會改成在本機編譯，這時需要先裝好 Python 和 C++ 編譯工具（Windows 是 Visual Studio Build Tools，Linux 是 build-essential）。

03安裝程式

  1. 把專案資料夾放到主機上

    把整個 stack-c-sveltekit 資料夾複製到主機，例如 C:\scada\stack-c-sveltekit 或 /opt/scada/stack-c-sveltekit。node_modules、build、data、uploads 這幾個資料夾不用複製，之後會自動產生；如果是搬遷舊系統，請改看資料位置與備份。

  2. 安裝相依套件

    在專案資料夾內執行：

    cd stack-c-sveltekit
npm install

    最後出現 found 0 vulnerabilities 之類的訊息、沒有紅色的 ERR!，就是安裝成功。

04用模擬器試跑（不需要實體設備）

專案內附一個 Modbus TCP 模擬器，可以在還沒接上實體 Gateway 之前，先確認整套流程能動。這一節用的是開發模式，只適合試用，正式上線請看下一節。

  1. 開第一個終端機，啟動模擬器 
    npm run simulator

    看到下面的訊息就代表模擬器在 127.0.0.1:15020 上提供 32 個線圈（位址 0–31，Slave ID 1）：

    Modbus TCP simulator listening on 127.0.0.1:15020 (unit id 1)
Coils: 32 (addresses 0-31)
Initial ON coils: 0, 2
  2. 開第二個終端機，啟動開發伺服器 
    npm run dev

    打開終端機上顯示的網址（通常是 http://localhost:5173）。

  3. 建一筆設備指向模擬器

    到「編輯模式」→ Devices，填 IP 127.0.0.1、Port 15020、Slave ID 1，再建空間和迴路。詳細步驟見配置使用：第一次配置。

模擬器的位址可以用環境變數修改：

變數預設值說明
SIM_HOST127.0.0.1監聽位址
SIM_PORT15020監聽 port
SIM_UNIT_ID1Slave / Unit ID
SIM_COIL_COUNT32線圈數量
 
$env:SIM_PORT = 1502; npm run simulator
SIM_PORT=1502 npm run simulator

在模擬器的終端機按 Ctrl+C 停掉它，就能模擬設備離線：一個輪詢週期內，畫面上該設備的迴路會變成紅色斜線的「離線」圖示；重新啟動模擬器後會自動恢復。

05正式部署

  1. 建立設定檔

    複製範本，再依照這台主機的情況修改（每一項的說明見下一節）：

    copy .env.example .env
notepad .env
    cp .env.example .env
nano .env

    最重要的是 TRUSTED_ORIGINS：把操作人員會在瀏覽器網址列輸入的每一種網址都列上去，包含 http:// 和 port。

    HOST=0.0.0.0
PORT=3000
BODY_SIZE_LIMIT=200M
LOG_LEVEL=info
TRUSTED_ORIGINS=http://localhost:3000,http://192.168.1.10:3000,http://scada-pc:3000
  2. 建置正式版 
    npm run build

    最後出現 ✔ done，並產生 build/ 資料夾，就是建置成功。

  3. 啟動 
    npm start
    [...] [INFO] [modbus-poller] server starting
[...] [INFO] [scheduler] scheduler starting
Listening on http://0.0.0.0:3000

    用瀏覽器打開 http://<主機 IP>:3000 確認畫面正常。關閉終端機程式就會停止，要開機自動執行請看設成常駐服務。

  4. 驗證

    開啟 http://<主機 IP>:3000/api/healthz，應該會看到 "status":"ok"。接著到編輯模式上傳一張平面圖：如果失敗並出現 403，代表你用的網址不在 TRUSTED_ORIGINS 裡（見疑難排解）。

改了 .env 之後要做什麼？

TRUSTED_ORIGINS 在建置時寫進程式，修改後要重新 npm run build 再重啟。其他設定（PORT、HOST、BODY_SIZE_LIMIT、LOG_LEVEL）只要重啟就會生效。

06.env 設定說明

設定何時生效說明
HOST重啟監聽的網路介面。0.0.0.0 表示區網內其他電腦都能連；127.0.0.1 表示只有本機能連。
PORT重啟網頁的 port，預設 3000。
BODY_SIZE_LIMIT重啟單一請求的大小上限。預設只有 512K，平面圖（最大 10MB）和備份檔（包含所有平面圖）都會超過，建議設 200M。
LOG_LEVEL重啟debug / info / warn / error。紀錄會同時輸出到終端機和 data/app.log。
TRUSTED_ORIGINS重新建置允許上傳檔案（平面圖、備份還原）的來源網址，以逗號分隔，每個都要包含 http:// 和 port。不在名單裡的網址，上傳時會被拒絕（403）。

07設成常駐服務（開機自動啟動）

以下是常見的兩種做法，請依主機的作業系統擇一。重點只有一個：工作目錄必須是專案資料夾，因為資料庫和上傳檔案都存在工作目錄底下的 data/、uploads/。

Windows：用 NSSM 註冊成服務

下載 NSSM，解壓縮後用系統管理員身分開啟 PowerShell：

nssm install ScadaLighting "C:\Program Files\nodejs\node.exe" "--env-file-if-exists=.env build"
nssm set ScadaLighting AppDirectory "C:\scada\stack-c-sveltekit"
nssm set ScadaLighting AppStdout "C:\scada\stack-c-sveltekit\data\service.log"
nssm set ScadaLighting AppStderr "C:\scada\stack-c-sveltekit\data\service.log"
nssm set ScadaLighting Start SERVICE_AUTO_START
nssm start ScadaLighting

之後可以在「服務」（services.msc）裡啟動、停止、重新啟動 ScadaLighting。

Linux：用 systemd

建立 /etc/systemd/system/scada-lighting.service：

[Unit]
Description=Lighting SCADA
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=scada
WorkingDirectory=/opt/scada/stack-c-sveltekit
ExecStart=/usr/bin/node --env-file-if-exists=.env build
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now scada-lighting
sudo systemctl status scada-lighting
journalctl -u scada-lighting -f     # 即時查看紀錄

User= 請換成實際執行服務的帳號，該帳號要有專案資料夾的讀寫權限；ExecStart 裡 node 的路徑可以用 which node 查詢。

08網路與防火牆

  • 進來的連線：開放網頁 port（預設 TCP 3000），讓操作人員的電腦連得到。
  • 出去的連線：主機要能連到每台 Gateway 的 Modbus TCP port（通常是 502）。
New-NetFirewallRule -DisplayName "Lighting SCADA" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow
sudo ufw allow 3000/tcp

要確認主機連得到 Gateway，可以在 PowerShell 執行 Test-NetConnection 192.168.1.50 -Port 502（IP 換成你的 Gateway），結果裡的 TcpTestSucceeded 應該是 True。

09資料位置與備份

路徑內容
data/scada.db所有設定：空間、設備、迴路、座標、場景、排程。旁邊的 -wal、-shm 是 SQLite 的工作檔，也屬於資料庫的一部分。
data/app.log系統紀錄，超過 5MB 會自動輪替成 app.log.1。
uploads/floorplans/上傳的平面圖。

建議用系統內建的備份功能（編輯模式 → 備份與還原 → 下載備份）。它會先把資料庫整理成單一檔案，再和平面圖一起打包成一個 zip，最不容易出錯。操作方式見配置使用：備份與還原。

如果要直接複製檔案（例如搬到新主機），請先停止服務，再複製整個 data/ 和 uploads/ 資料夾。服務執行中直接複製 scada.db，可能會漏掉還在 -wal 檔裡的資料。

10升級更新

  1. 先備份

    從系統下載一份備份 zip。

  2. 停止服務

    Windows：nssm stop ScadaLighting；Linux：sudo systemctl stop scada-lighting。

  3. 更新程式檔

    用新版覆蓋專案資料夾內的程式檔。保留 data/、uploads/ 和 .env。

  4. 重新安裝並建置
    npm install
npm run build
  5. 啟動服務並確認

    啟動後開啟 /api/healthz 和操作頁面，確認設定都還在、燈號正常更新。

    啟動時會自動建立缺少的資料表，但不會修改既有資料表的欄位。如果新版本的說明提到資料庫結構有變動，請依照該版本的指示處理；出問題時可以用第一步的備份還原。

11疑難排解

狀況原因與處理
上傳平面圖或還原備份時出現 Cross-site POST form submissions are forbidden（403） 瀏覽器網址列上的網址不在 TRUSTED_ORIGINS 裡。把它（含 http:// 和 port）加進 .env，然後重新 npm run build 再重啟。用 IP 和用主機名稱連線算是不同的網址，要分別列出。
上傳大檔案失敗，或備份還原失敗 BODY_SIZE_LIMIT 太小，或者根本沒設（預設只有 512K）。改成 200M 後重啟。
迴路全部顯示紅色斜線加「?」 伺服器連不到該設備。先到「系統狀態」頁看連線狀態和連續失敗次數，再檢查 Gateway 的 IP、Port、Slave ID，以及主機到 Gateway 的網路和防火牆（見網路與防火牆）。
啟動時出現 EADDRINUSE 這個 port 已經有別的程式在用（也可能是同一套系統已經在跑）。改 .env 的 PORT，或先停掉占用這個 port 的程式。
npm install 在 better-sqlite3 失敗 沒有找到預先編譯好的檔案，而本機又缺少編譯工具。請確認 Node.js 版本符合需求，並安裝 Python 和 C++ 編譯工具後重試（見環境需求）。
排程觸發的時間不對 排程用的是伺服器主機的本機時間，請檢查主機的時區和時鐘。
還原備份後，資料看起來還是舊的 資料庫要在下一次啟動時才會換成備份的內容（平面圖則是立即生效）。重新啟動服務即可。
npm start 出現找不到 build 還沒建置。先執行 npm run build。

要看更詳細的紀錄，可以把 LOG_LEVEL 改成 debug 後重啟，再查看 data/app.log。

12安全注意事項

只能在受信任的內部網路使用
  • 系統沒有登入機制：只要連得到網頁的人，都能開關燈、修改設定、還原備份。
  • 連線沒有加密（HTTP）。
  • 不要把網頁 port 開放到網際網路。需要遠端存取時，請透過 VPN。

外部系統要串接控制燈光，請參考專案內的 EXTERNAL_API.md；完整的 API 說明在 API.md。
